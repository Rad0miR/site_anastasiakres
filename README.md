# Kres AI

Персональный сайт-портфолио AI-креатора Kres AI.
React + Vite + Tailwind CSS + Framer Motion.

## Версии сайта

В проекте живёт несколько независимых сайтов. Старые не удаляются и
остаются доступными по своим адресам:

| Адрес | Что это                            | Код       |
| ----- | ---------------------------------- | --------- |
| `/`   | актуальная версия (сейчас `v3`)    | `src/v3/` |
| `/v1` | первая версия, заморожена          | `src/v1/` |
| `/v2` | вторая версия, заморожена          | `src/v2/` |
| `/v3` | третья версия — сайт Kres AI       | `src/v3/` |

Адрес `/v3` работает и сейчас, пока эта версия актуальная, и потом, когда
её сменит следующая: ссылку на версию можно давать в любой момент, она не
протухнет. На `/` всегда та версия, которая указана в `CURRENT`
(`src/versions.js`), туда же ведут все несуществующие адреса.

Роутера нет и не нужно: это не страницы одного приложения, а несколько
разных приложений. Переход между ними — обычная ссылка с полной
перезагрузкой, поэтому стили и шрифты одной версии физически не попадают
на другую. Код версии грузится отдельным файлом и только по её адресу —
посетитель главной ничего лишнего не скачивает.

### Что у версии своё

Всё, кроме трёх общих файлов (`src/main.jsx`, `src/index.css`,
`src/versions.js`) и общего серверного адреса `/api/contact`
(см. [«Форма связи»](#форма-связи-lets-connect-)):

| Своё                    | Где                                    |
| ----------------------- | -------------------------------------- |
| вёрстка и компоненты    | `src/v3/App.jsx`, `src/v3/components/` |
| тексты на трёх языках   | `src/v3/data/content/`                 |
| ссылки и списки         | `src/v3/data/`                         |
| картинки                | `src/v3/assets/`                       |
| цвета, шрифты, тени     | `src/v3/tokens.js`                     |
| остальное оформление    | `src/v3/v3.css`                        |
| шрифты, title, описание | запись версии в `src/versions.js`      |

Токены версии попадают в Tailwind с её префиксом: `ink` из
`src/v3/tokens.js` превращается в утилиту `bg-v3-ink`. Поэтому у новой
версии могут быть свои `ink`, `card` и `silk` с любыми значениями — это
будут другие утилиты, и старая версия их не заметит. То же с CSS: классы
`.v3-glass`, переменные `--v3-ink`, глобальные правила только внутри
`html.v3`.

Подробности: [`src/v3/README.md`](src/v3/README.md),
[`src/v2/README.md`](src/v2/README.md) и
[`src/v1/README.md`](src/v1/README.md).

## Как выпустить новую версию

Скажем, `v4`. Работа над ней не мешает посетителям: пока `CURRENT` не
переключён, на `/` остаётся прежний сайт, а новый открывается на `/v4` —
там его можно показывать и обсуждать.

1. **Папка.** `src/v4/` — по образцу `src/v3/`: `App.jsx`, `tokens.js`,
   `v4.css`, `assets/`, `components/`, `data/`. Копировать `v3` целиком не
   обязательно: общего кода у версий нет, и новая может быть устроена как
   угодно.

2. **Префикс.** Всё, что принадлежит версии, начинается с `v4`: имена в
   `tokens.js` (в разметке они станут `bg-v4-ink`), классы в `v4.css`
   (`.v4-glass`), переменные (`--v4-ink`), а глобальные правила пишутся
   внутри `html.v4` — класс вешает `App.jsx` версии, как в `v3`.

3. **Токены — в общий конфиг.** В `tailwind.config.js` две строки:
   `import v4 from './src/v4/tokens.js'` и `{ prefix: 'v4', tokens: v4 }`
   в списке `VERSIONS`.

4. **Запись в реестре.** В `src/versions.js` добавить версию: `id`,
   `lang`, `title`, `description`, `themeColor`, ссылка на шрифты и
   `load: () => import('./v4/App.jsx')`.

5. **Готово — переключить.** В `src/versions.js` поставить
   `CURRENT = 'v4'`, а в `index.html` заменить `title`, `description`,
   `theme-color`, `lang` у `<html>` и ссылку на шрифты — на значения новой
   версии (те же, что в её записи реестра).

Больше ничего: прошлая версия остаётся на своём адресе, её файлы не
трогаются, хостинги донастраивать не нужно. Старые версии помечаются
`noindex`, чтобы не конкурировать в поиске с актуальной, — это делает
`src/main.jsx` по `CURRENT`.

### Чего делать нельзя

- Писать в `theme` мимо `theme.extend` в `tailwind.config.js` —
  стандартные утилиты Tailwind общие для всех версий.
- Заводить в `tailwind.config.js` токены без префикса версии.
- Добавлять оформление в `src/index.css` — его видят все версии, включая
  замороженные.
- Брать что-то из папки другой версии. Нужен тот же компонент — скопируйте.

## Структура главной страницы (версия `v3`)

Один длинный экран:

```
Hero  →  Content Types  →  Content Styles  →  Social  →  Связаться  →  Финальный визуал  →  Footer
```

Соцсети стоят после «MY VISUAL WORLD» и всех связанных с ним картинок:
сначала посетитель смотрит работы, потом узнаёт, где искать ещё, — и там
же, в середине страницы, ему предлагают написать. Финальный визуал
закрывает страницу.

| Блок               | Компонент                             | Что внутри                                        |
| ------------------ | ------------------------------------- | ------------------------------------------------- |
| Hero               | `v3/components/Hero.jsx`              | фон-фотография, поверх — HTML-текст и две кнопки  |
| ↳ шапка            | `v3/components/Header.jsx`            | логотип, «Let’s connect ♡», выбор языка           |
| ↳ приветствие      | `v3/components/Intro.jsx`             | личное обращение автора над «WELCOME TO»          |
| ↳ выбор языка      | `v3/components/LanguageSwitch.jsx`    | круглая кнопка с глобусом и список из трёх языков |
| Content Types      | `v3/components/ContentTypes.jsx`      | 11 категорий: только текст и контурные значки     |
| Content Styles     | `v3/components/ContentStyles.jsx`     | 11 карточек-кнопок + раскрытие картинки           |
| Большой визуал     | `v3/components/Showcase.jsx`          | слот; рисуется, только если есть файл `showcase`  |
| Social             | `v3/components/SocialRow.jsx`         | 6 площадок в одну строку, на узком — карусель     |
| Связаться          | `v3/components/ConnectInvite.jsx`     | приглашение написать и вторая «Let’s connect ♡»   |
| ↳ форма            | `v3/components/ConnectDialog.jsx`     | окно с тремя полями и кнопкой «SEND ♡»            |
| Финальная картинка | `v3/components/Finale.jsx`            | закат и «A BRIGHTER TOMORROW»                     |
| Footer             | `v3/components/Footer.jsx`            | логотип, копирайт, фраза справа                   |

Две кнопки первого экрана ведут вниз по якорям из `v3/data/anchors.js`:
«Content types ↓» — к «WHAT I CREATE», «My socials ↓» — к «WHERE YOU CAN
FIND ME». Обе кнопки «Let’s connect ♡» — в шапке и под соцсетями — никуда
не ведут: они открывают форму связи, см. ниже.

### Три языка

Кнопка с глобусом в шапке переключает сайт между 🇺🇦 українською,
🇬🇧 english и 🇩🇪 deutsch. Выбор запоминается в браузере (`localStorage`,
ключ `kres-v3-lang`) и проставляется в `<html lang>`; по умолчанию сайт
открывается на английском.

Весь текст лежит в трёх файлах одинакового устройства —
`src/v3/data/content/{en,uk,de}.js`. Поменять формулировку значит открыть
нужный файл и поправить одну строку; вёрстку трогать не нужно. Не
переводятся только имена собственные: «Kres AI», названия площадок и
бренды внутри названий стилей.

Языки перечислены в `src/v3/data/content/index.js` — там же порядок в
списке и язык по умолчанию. Чтобы добавить четвёртый, достаточно положить
рядом ещё один файл по образцу `en.js` и дописать его туда.

### Как работает нажатие на стиль

Карточка стиля — это `<button>`, а не ссылка. Нажатие не открывает ни новый
адрес, ни окно поверх сайта: между каруселью и нижней частью страницы
раскрывается панель с выбранной картинкой, и всё, что ниже, съезжает вниз.
Повторное нажатие на ту же карточку закрывает панель.

Какой стиль сейчас раскрыт — одно из трёх состояний версии. Оно живёт
в `src/v3/App.jsx`, потому что нужно двоим: карусели и нижним секциям
(`LayerBelow` там же добавляет им доводочный ход, чтобы сдвиг читался как
движение, а не как перерисовка). Второе состояние — выбранный язык, оно
в `src/v3/lib/language.jsx`; третье — открыта ли форма связи, оно
в `src/v3/lib/connect.jsx`.

## Форма связи «Let’s connect ♡»

Кнопка «Let’s connect ♡» стоит в двух местах — в шапке и под блоком
соцсетей, посреди страницы, — и открывает одно и то же окно поверх сайта.
Отдельной страницы у формы нет.

В форме три поля («Как к вам обращаться», «Как с вами связаться», «Ваш
вопрос или заказ») и кнопка «SEND ♡». Путь заявки:

```
форма (браузер)  →  POST /api/contact  →  серверная функция  →  Telegram Bot API  →  закрытая группа
```

В группу приходит вот такое сообщение:

```
NEW REQUEST — Kres AI ♡

Name: Anastasia
Contact: @username
Request: I would like to create UGC content for my brand…
```

**Заявка нигде не сохраняется.** Ни на сайте, ни в `localStorage`, ни
в адресной строке: набранный текст живёт только в состоянии компонента и
исчезает вместе с закрытым окном. После успешной отправки посетитель видит
«Thank you! Your message has been sent. ♡», форма очищается и окно
закрывается само. Если отправить не удалось — по любой причине — внизу
формы появляется «Something went wrong. Please try again.»: ни ответа
Telegram, ни кода ошибки посетителю не показывают, подробности уходят
в лог хостинга.

### Токен бота

**Токен не хранится в коде и не попадает в браузер.** Он живёт только
в переменных окружения на стороне сервера — вместе с id группы:

| Переменная           | Что это                                              |
| -------------------- | ---------------------------------------------------- |
| `TELEGRAM_BOT_TOKEN` | токен бота из [@BotFather](https://t.me/BotFather)    |
| `TELEGRAM_CHAT_ID`   | id закрытой группы, число вида `-1001234567890`       |

Где их задать на хостинге — в разделе [«Деплой»](#деплой). Локально —
в файле `.env` в корне проекта (он в `.gitignore`, образец —
[`.env.example`](.env.example)).

Узнать `TELEGRAM_CHAT_ID`: добавить бота в группу, написать там
`/start@ИмяБота` (именно с `@` — иначе при включённом режиме приватности
бот сообщения не увидит) и запустить

```bash
npm run telegram:chat-id
```

Скрипт покажет все чаты, которые бот видел, и отметит стрелкой группы.

### Где что лежит

| Файл                       | Что делает                                             |
| -------------------------- | ------------------------------------------------------ |
| `server/contact.js`        | **вся** логика: проверка полей и отправка в Telegram    |
| `server/dev-api.js`        | тот же обработчик на `npm run dev`                      |
| `netlify/functions/contact.mjs` | обёртка для Netlify                                |
| `functions/api/contact.js` | обёртка для Cloudflare Pages                            |
| `worker/index.js`          | обёртка для Cloudflare Workers (`wrangler.toml`)        |
| `scripts/telegram-chat-id.mjs` | вспомогательный скрипт, узнать id группы            |

Обёртки одинаковые и состоят из одной строки: разворачивать сайт можно
куда угодно из этих трёх мест, логика от площадки не зависит. Меняя
поведение формы, правьте `server/contact.js` — больше нигде его нет.

Из защиты от роботов в форме есть спрятанное поле `website`: человек его
не видит и не заполнит, а автозаполнялка заполнит — такую заявку сервер
молча выбрасывает, отвечая как при успехе.

## Запуск

Нужен [Node.js 20+](https://nodejs.org).

```bash
npm install
```

```bash
npm run dev
```

Сайт откроется на `http://localhost:5173`, прошлые версии — на `/v1` и `/v2`,
актуальная — там же на `/v3`.

Форма связи работает и локально: `npm run dev` поднимает `/api/contact`
тем же кодом, что и хостинг. Чтобы заявки доходили до Telegram, положите
рядом `.env` с двумя переменными (образец — [`.env.example`](.env.example));
без него форма честно покажет «Something went wrong».

Сборка в папку `dist`:

```bash
npm run build
```

## Картинки

Подключаются по имени файла, без импортов в коде: положил `hero.webp`
в `src/v3/assets/` — сайт сразу его показывает. Расширение любое.
Подробности: [`src/v3/assets/README.md`](src/v3/assets/README.md).

Одного файла пока нет — `showcase` (широкий кадр между стилями и закатом).
Секция без него просто не рисуется; появится файл — встанет на место сама.

## Раскладка

Мобильная версия — не уменьшенная десктопная: composition собирается заново.

- **Телефон** — герой во весь экран, приветствие вверху, остальной текст
  в нижней трети над затемнением; обе кнопки помещаются в одну строку;
  соцсети и стили не переносятся на вторую строку, а листаются вбок
  (полоса прокрутки скрыта); категории в две колонки.
- **Планшет (от 768px)** — все шесть соцсетей помещаются в строку,
  категории в четыре колонки, стили по-прежнему листаются.
- **Десктоп (от 1280px)** — все 11 карточек стилей видны разом,
  категории в шесть колонок, соцсети — иконка слева, подпись справа.

## Деплой

Куда бы сайт ни разворачивался, ему нужны **две переменные окружения** —
иначе форма связи не отправит ни одной заявки:
`TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` (см.
[«Форма связи»](#форма-связи-lets-connect-)). Токен задавайте как секрет:
в репозитории его нет и быть не должно.

### Netlify

Всё уже настроено в `netlify.toml`. Подключи репозиторий — Netlify сам
подставит команду и папку. Либо вручную:

- Build command: `npm run build`
- Publish directory: `dist`
- Site configuration → Environment variables: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`

Серверную функцию Netlify находит сам: она лежит в `netlify/functions/`
и отвечает на `/api/contact`.

### Cloudflare Pages

- Framework preset: **Vite**
- Build command: `npm run build`
- Build output directory: `dist`
- Variables and Secrets: `NODE_VERSION` = `20`, `TELEGRAM_BOT_TOKEN` (Secret), `TELEGRAM_CHAT_ID`

Функция `/api/contact` — в папке `functions/api/`, Pages подключает её сам.

### Cloudflare Workers (`wrangler deploy`)

Настроено в `wrangler.toml`: статика раздаётся из `dist`, а `/api/contact`
обслуживает `worker/index.js`. Переменные — Settings → Variables and
Secrets, токен как Secret. Локально их подставляет `.dev.vars`.

Заголовки кэширования лежат в `public/_headers` — работают на обеих платформах.

Адреса версий работают без дополнительных настроек: обе платформы уже отдают
`index.html` на любой путь — `netlify.toml` (redirect 200) и `wrangler.toml`
(`not_found_handling`). Новая версия ничего в этих файлах не меняет.

## Особенности

- Уважает `prefers-reduced-motion` — движение гасится и в CSS, и в Framer Motion.
- Картинки переведены в `.webp`: все 13 весят около 1,5 МБ вместо 25 МБ исходных
  PNG. Ниже первого экрана они грузятся лениво.
- Внешние ссылки открываются с `rel="noopener noreferrer"`.
- Шрифты грузятся с Google Fonts, есть системный фолбэк. У каждой версии свои:
  Plus Jakarta Sans, Manrope, Cormorant Garamond и Caveat — у `v3`,
  Inter, Playfair Display и Marck Script — у `v1`. Чужие не загружаются.
- Manrope в `v3` стоит второй в стеке основного гротеска не как запасной
  вариант, а как пара к первому: **своей кириллицы у Plus Jakarta Sans
  нет**, и без Manrope украинский текст набирался бы системным шрифтом.
  Латиница всегда достаётся Jakarta, поэтому английский и немецкий
  выглядят ровно как раньше, а кириллический файл браузер скачивает
  только тогда, когда на странице появились кириллические буквы.
- Выбранный язык хранится в браузере посетителя и никуда не отправляется.
  Приватный режим и запрет на хранение данных сайт переживает: язык
  просто не запомнится до следующей загрузки.
- Заявка из формы связи не сохраняется нигде: ни на сайте, ни в браузере.
  Она уходит прямо в Telegram и живёт дальше только там.
